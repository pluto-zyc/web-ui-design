# 组件库优先与封装策略

## 项目库识别

扫描前端 package manifest、组件注册入口、样式入口与实际使用代码，确认已安装的组件库、图标库和项目封装。Registry 只记录真实存在的内容，并区分 `existing`、`added`、`planned` 等状态。

项目没有组件库时，继续使用项目原有实现；只有任务需要且用户允许时才引入新依赖。技能不得假定每个项目都使用同一个组件库。

## 使用与封装

优先使用适配当前 project profile 的项目包装组件。没有包装组件时，优先采用已安装组件库的控件与交互能力，再应用项目 Token 和稳定的项目默认值。

当某种结构在多页复用、具有稳定的外观或业务约束，或用户要求统一封装时，可以建立项目级包装组件，例如 `BaseTable`、`AdminTable`、`VisualizationTable`、`BaseFormField`。普通基础控件若只需统一 CSS 变量、默认值或项目主题，不必为每个控件再套一层。

包装组件应：

- 明确适用的 profile 和视觉主题；
- 保留底层组件的常见 props、events 和 slots，避免封装后无法扩展；
- 由页面/业务层提供数据，组件层负责显示、交互和一致性；
- 仅开放稳定且实际需要的变体，避免累积大量一次性参数；
- 在加入 Registry 前确认源码实现、路径、契约和状态。

## 列表与表格

共享表格组件拥有已登记的默认视觉样式。参考图中的表格样式与项目主题冲突时，默认沿用共享表格主题；仅当用户要求页面级参考图保真或变更列表主题时才创建/选择额外变体。

Page Schema 仍要描述列、字段、排序/筛选、操作、选择、分页和数据状态。页面实现通过列配置、具名插槽、事件等配置共享组件，不重复实现它的表头、行高、边框、状态色和分页视觉。

先覆盖项目大多数表格场景。树形、分组表头、可编辑网格、实时滚动等显著不同的模式可以作为有明确名称和契约的变体或独立组件，不强行塞进一个 BaseTable。

表格包装组件不应直接请求特定业务 API。它接收行数据和列定义，输出选择、排序、筛选和分页等事件；业务页或数据层负责 API 和权限逻辑。

## 主题变量与隔离

从项目 Design Token 映射组件库主题。主色之外，检查 hover、active、focus、disabled、border、surface、text 与语义状态色；不要只设置一个 brand 值后就宣称所有状态已统一。

同一应用存在后台与可视化两个主题时：

- 使用分开的主题根节点或有命名空间的包装组件；
- 避免单页需求导致全局覆盖 `.el-*` 内部选择器；
- 优先选择组件库公开的 props、slots、CSS variables 和 class hooks；
- Vue 页面样式通常保持 `scoped`，确需修改内部元素时使用窄范围 `:deep()`；
- 组件可能把 popper/dialog 内容 teleported 到 `body`。这类节点不会继承主题根的变量，应使用库提供的 popper class、append target 或 overlay class 进行主题连接，并验证打开后的状态。

## 页面与组件职责

Page Schema 表达页面结构与内容配置。Registry 表达共用组件可提供的稳定契约。Design Token 表达全局或 profile 主题规则。不要把一张参考图的单次差异直接升级成新的全局默认值。
